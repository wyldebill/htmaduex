# mapme

Simple Flutter Google Maps app with a single screen and a **Find Me** button.

> This project is intentionally configured for **Android + iOS only**.

## Secret handling (no key in git)

1. Prefer platform config files generated by the Firebase Console or the FlutterFire CLI:
   - Android: place `android/app/google-services.json` (download from the Firebase console) or run `flutterfire configure`.
   - iOS: place `ios/GoogleService-Info.plist` or run `flutterfire configure`.
2. Keep these platform config files out of git (they are platform-specific). Do not rely on storing Firebase web/API keys as required Gradle environment variables.
3. For local testing you can keep a `.env` with only `GOOGLE_MAPS_API_KEY` if you need Maps; Firebase values are optional. The app prefers `lib/firebase_options.dart` (generated by `flutterfire configure`) or the platform files.

Tip: Run `flutterfire configure` to generate `lib/firebase_options.dart` and wire up Android/iOS platform files automatically.

## Local development

1. Install deps:
   `flutter pub get`
2. Generate iOS secret config from `.env`:
   `powershell -ExecutionPolicy Bypass -File .\tool\sync_secrets.ps1`
3. Run:
   `flutter run`

For macOS/Linux shells:
`bash ./tool/sync_secrets.sh .env`

## VS Code debugging

Before first iOS debug session, run `tool/sync_secrets.ps1` (or `.sh`) so `ios/Flutter/Secrets.xcconfig` exists.

Android reads `.env` directly via Gradle each build.

## Codemagic

`codemagic.yaml` expects these environment variables:
`GOOGLE_MAPS_API_KEY`, `FIREBASE_API_KEY`, `FIREBASE_APP_ID`, `FIREBASE_MESSAGING_SENDER_ID`, `FIREBASE_PROJECT_ID`, `FIREBASE_AUTH_DOMAIN`, `FIREBASE_STORAGE_BUCKET`, `FIREBASE_IOS_BUNDLE_ID`.

CI writes `.env` at build time, generates iOS xcconfig, runs tests, and builds Android APK.
